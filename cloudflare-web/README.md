# 점핑배틀 다른 지점용 웹 소스

현재 운영 중인 원본 지점 사이트와 분리해 전달하기 위한 웹 소스입니다.
원본 지점의 실제 운영 데이터, 배포 연결값, 비밀키, 관리자 PIN, 네이버 사업장·상품 번호,
브릿지 프로그램, 네이버 수집 확장 프로그램은 포함하지 않았습니다.

## 매장별 상의 후 반드시 설정할 항목

| 항목 | 위치 | 초기 상태 |
| --- | --- | --- |
| 매장명 | `app/store-profile.ts` | `매장별 상의` |
| 방 구성·권장 인원·맵 번호 | `app/reservation-config.ts`, `db/control.ts` | 예시 구조, 매장별 상의 |
| 가격·부가매출 단가 | `app/pricing-config.ts` 및 관리자 설정 화면 | 예시값 |
| 네이버 예약 상품 ID | `db/naver-stock.ts` | 모두 `0`, 연동 비활성 |
| 관리자 PIN·브릿지 토큰·로그인 비밀키 | `.env.example` 참고 | 새 값 발급 필요 |
| 사이트 주소·데이터베이스·배포 프로젝트 | `.openai/hosting.json` 참고 | `매장별-상의`, 새 프로젝트 발급 필요 |
| 브릿지 및 네이버 예약 수집 연동 | 별도 설치·설정 | 이 압축파일에 미포함 |

## 안전 주의사항

- 기존 원본 지점의 사이트 주소, 프로젝트, 데이터베이스, PIN, 토큰을 다른 지점과 공유하지 마세요.
- 새 지점은 반드시 별도 사이트와 빈 데이터베이스를 만들어야 합니다.
- `.openai/hosting.json`의 `매장별-상의`는 안전한 표시용 값이므로 실제 배포 전에 새 프로젝트 ID로 교체해야 합니다.
- `db/naver-stock.ts`의 상품 ID가 `0`인 동안 네이버 재고 연동은 동작하지 않습니다.
- 실제 관리자 프로그램 원격 제어는 그 지점 전용 브릿지를 별도로 설치한 뒤 연결해야 합니다.
- 운영 전 방 순서, 맵 번호, 가격, 네이버 예약 상품을 실제 장비와 함께 확인해야 합니다.

## 포함된 웹 기능

- 고객 당일 예약 화면
- 관리자 통합 운영 화면과 전체 시간대별 예약 현황
- 예약·결제 수정 및 매출 분석
- 매장 원격제어 명령 API
- 네이버 예약 수신 및 재고 계획 API
- 데이터베이스 구조와 배포용 웹 설정

## 개발 확인

```powershell
pnpm install
pnpm run test
pnpm run dev
```

이 전달본은 웹 소스만 포함하며, 현재 운영 사이트에는 아무 변경도 하지 않습니다.
